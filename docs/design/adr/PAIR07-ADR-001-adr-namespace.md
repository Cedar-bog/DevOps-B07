# PAIR07-ADR-001：ADR 命名空间与跨组引用

- 状态：Accepted
- 命名空间：`PAIR07-ADR-*` = A07 / B07 双方共同决策
- 日期：2026-09-22
- 关联任务：E2-B07-015（J5）

## Context

A07 与 B07 各自维护 ADR 目录，编号独立递增，已经产生同名不同物的冲突：

| 编号 | A07 的含义 | B07 的含义 |
|---|---|---|
| `ADR-002` / `0002` | 查询响应格式（`ADR-002-job-query-response.md`） | 产物传递与可追溯性（`B07-ADR-0002-artifact-passing.md`） |

配对组之间要互相引用对方的决策（例如 B07 的 `B07-ADR-0001` 引用 A07 的查询响应约定），裸编号无法消歧。强制两边协商出全局唯一编号空间可以消除歧义，但需要持续维护一个跨组织编号表，成本高、收益低。

另一个独立问题：J1–J4 这类交接约定（产物解析入口、保留策略、错误码分域、版本同步）是**双方共同决策**，不属于任何一方。若强行塞进某一方的编号序列，日后会反复出现「这份 ADR 算谁的」。

## Decision

**编号只保证仓库内唯一；跨组共同决策另开命名空间。**

| 命名空间 | 归属 | 用途 |
|---|---|---|
| `B07-ADR-NNNN` | B07 单方 | B07 内部决策（原 `0001` / `0002` 已迁至此） |
| `A07-ADR-NNN` | A07 单方 | A07 内部决策（沿用 A07 现状编号） |
| `PAIR07-ADR-NNN` | 双方共同 | 交接约定；J1–J4 的结论落在此 |

**跨组引用一律带组名前缀**，写作 `A07:ADR-002`、`B07:ADR-0002`、`PAIR07-ADR-002`。本仓内引用同命名空间的文件可省略前缀，跨命名空间引用必须带前缀。

三者存放于同一目录 `docs/design/adr/`，由文件名前缀区分——命名空间是编号约定，不要求物理分目录。

## Alternatives

- **强制全局唯一编号**：两边协商统一的编号空间，任何一方新增都要避开对方已用号段。彻底消除歧义，但引入一个需要双边维护的共享编号表，且每次新增 ADR 都要跨组确认；与「编号只是文档索引」的定位不成比例。
- **裸编号 + 完整路径引用**：保持各自编号，引用时写全路径。能消歧，但路径随重构漂移，且**没有表达归属**——读者无法从 `ADR-002` 判断这是谁的决策、需不需要对方确认。
- **按方分目录**（`adr/a07/`、`adr/b07/`）：物理隔离直观，但共同决策仍需第三处落脚，且把「命名空间」问题偷换成「目录结构」问题。

## Consequences

### 正面

- 引用即自描述：`A07:ADR-002` 一眼看出归属与是否需要对方确认。
- 共同决策有了明确归宿，不再出现「这份 ADR 算谁的」。
- 双方各自编号空间独立，新增 ADR 无需跨组协调。
